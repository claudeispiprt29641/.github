<p>用 ISP 住宅出口踩坑，症状往往长得很像：都是「打不开」「要验证」「传一半断了」。但背后的原因可能完全相反，一个是出口类型被归类，一个是复用率太高，一个是线路抖动，还有一个压根跟出口无关。这篇按故障树的方式写：先归类症状，再逐条分支往下查，每个分支给判定动作和退出条件，避免把四类问题混成一个「IP 不干净」。</p>

<h2>一、先把「不对劲」归成四类症状</h2>
<p>四类症状的区分标准很简单，看三件事：是否所有访问都异常、是否只有这个账号异常、是否集中在某个时段。三个问题问完，基本能落到一条分支上。</p>

<p>先把这张表填了，再往下走。跳过归类直接换 IP，是浪费时间最常见的方式。</p>
<h3>判定前先做一件事：固定观测窗口</h3>
<p>至少要连续 48 小时、每天三个时段各测一次，才能定性。单次异常不构成证据，尤其 ISP 住宅线路在晚高峰的抖动本来就有随机性。</p>

<h2>二、分支一：出口被归到机房段</h2>
<p>ISP 住宅出口被归到机房段，通常不是「IP 坏了」，而是这个段的注册信息本来就不像家宽。常见情形是运营商把一段地址批给二级转售商，转售商再切成小段卖给代理服务商，注册主体写的是公司而不是 ISP。这种段在 ipapi.is 里 company.type 常显示为 hosting 或 business。</p>
<p>判定动作：查 ipinfo.io 看 org 是不是 ISP 名称；查 ipapi.is 看 asn.type 与 company.type 是否都为 isp；查 bgp.he.net 看该 /24 的上游是谁。三项里有一项对不上，就不能算合规的家宽画像。</p>
<h3>能不能救</h3>
<p>基本不能。段的注册信息是上游分配的，改不了。唯一的办法是换段，而且要换到不同的上游。跟服务商沟通时直接说「这个 /24 的 company.type 是 hosting，请换一个 asn.type 与 company.type 都为 isp 的段」，比说「你们的 IP 不干净」有效得多。</p>

<h2>三、分支二：复用率过高带来的连带异常</h2>
<p>复用率是 ISP 住宅最容易被隐藏的指标。商品页写「独享」，实际可能是「同时在线会话不超过 5 个」。当这 5 个会话里有人在做高频请求，整条出口的画像就会被拖累，而你只是正常登录也会受影响。</p>
<p>判定动作：在同一出口上做一次「纯净度对照」——用这条出口访问一个与你业务无关的普通网站，看是否也被要求验证。如果连普通站点都异常，说明问题在出口整体，不在你的账号。再进一步，连续 24 小时每小时查一次出口 IP，确认它没有在多个 IP 之间漂移（漂移意味着你其实在一个池子里）。</p>

<h3>怎么向服务商要证据</h3>
<p>要三个数：这条 IP 当前绑定的会话数、近 7 天的峰值并发、同段其他 IP 的滥用投诉数。给不出来的，按高复用率处理。合同里如果能写「同时在线上限 1」，那才是真独享。</p>

<h2>四、分支三：线路抖动、超时和半开连接</h2>
<p>这一类跟身份无关，纯是网络问题。典型表现是上传大文件到 80% 断掉、长对话加载到一半停住、SSH 或长连接闲置几分钟后被重置。根因通常是三个：城域网段拥塞、NAT 表项超时、MTU 不匹配。</p>
<p>判定动作：mtr -c 200 看丢包是否集中在某一跳；ping -M do -s 1472 测 MTU，如果 1472 不通就往下试 1400、1360；抓一次断线前后的连接状态，看是不是 ESTABLISHED 直接变 CLOSE_WAIT。</p>
<h3>三个可落地的处理</h3>
<p>NAT 超时就把心跳压到 30 秒以内，别用默认的 300 秒；MTU 不匹配就把隧道 MTU 调到 1380 并开 MSS clamping；城域网拥塞只能换线路，优先选落地在骨干节点而非小区汇聚的段。这三条做完，大部分「传一半断」的问题会消失。</p>

<h2>五、分支四：账号侧环境不一致</h2>
<p>排查到这一步，出口已经证明是干净的，那问题就在账号侧。常见的不一致有四种：时区与出口地区不符、浏览器语言与登录地区不符、支付资料的国别与出口不符、以及同一账号在短时间内从两个地区登录。</p>
<p>判定动作：把账号资料、浏览器配置文件、支付信息、出口地区四项列出来对照。任何一项和出口地区不一致，都要先修正再谈换线。修正顺序是先改静态信息（资料、语言、时区），再改支付，最后才动网络。</p>
<h3>四个检查点</h3>
<p>时区用 IP 归属地时区而不是系统默认；语言首选项至少包含出口地区的主要语言；账单地址与出口同国；登录日志里不要出现一天内跨洲的记录。四项都对齐，再观察一周，多数异常会自然减少。</p>

<h2>常见问答</h2>
<h3>怎么快速判断是出口问题还是账号问题？</h3>
<p>答：用同一出口访问一个无关的普通网站。也被验证，是出口问题；只有目标站异常，先查账号侧。这一步两分钟能做完，能省掉大量反复换线的成本。</p>
<h3>ISP 住宅出口被识别成机房，能申诉吗？</h3>
<p>答：向服务商申诉换段比向平台申诉有效。段级归类是公开数据库的结果，个人申诉改不了，换一个 company.type 为 isp 的段才是解法。</p>
<h3>心跳设多少合适？</h3>
<p>答：30 秒是通用值。NAT 超时较短的网络可以压到 15 秒，但要注意别把心跳本身变成高频请求。连续 3 次心跳失败再判定断线，避免误判。</p>
<h3>换了三家还是同样症状，说明什么？</h3>
<p>答：说明问题大概率不在出口。三家共用同一个账号环境时，异常会稳定复现。这时候应该停下来做环境一致性核对，而不是继续换第四家。</p>

<h2>合规提示</h2>
<p>本文的排查方法用于定位自有账号的网络与环境问题，不用于探测或绕过平台访问控制。所有测试应遵守目标服务的调用频率限制。</p>
<p>排查过程中产生的日志可能包含账号标识与访问记录，应限制访问范围并按当地法规设定留存期限。涉及他人的账号数据时，须获得明确授权。</p>
